

# 1 使用手册

本文档用于说明部门管理员在系统中的主要可用功能。

## 1.1 首页

首页是部门管理员登录后的工作入口，可以用来快速了解当前系统和部门相关信息。结合当前已授权功能，首页通常会展示通知公告、待处理事项、工作项积分概览等内容。

如果使用了工作项积分模块，首页会比较有价值：可以快速看到本月积分、今日日报状态、待审核数量、工作项总数，也可以进入日报填写、日报审核和积分报表。Web 端首页还包含部门积分排行榜、部门个人积分趋势等看板，适合管理员每天先看一眼整体情况。

## 1.2 组织架构

组织架构是部门管理员维护人员和权限的基础入口。员工、部门、角色之间是关联的：员工归属部门，员工通过角色获得菜单和操作权限，角色又可以设置数据范围。

### 1.2.1 部门管理

部门管理用于维护组织层级。部门信息会影响员工归属、日报审核范围、积分报表统计范围等，所以调整部门时要注意层级是否正确。

如果只是日常查看部门结构，可以直接进入页面确认；如果要调整部门，建议先确认该部门下是否还有员工或业务数据，避免影响后续统计和权限范围。

### 1.2.2 员工管理

员工管理用于维护员工账号。常见场景包括新员工入职时添加账号、员工信息变化时编辑资料、人员调岗时调整部门、员工忘记密码时重置密码，以及离职或停用账号时进行禁用、启用或删除。

这里也可以维护部门信息。实际使用时，建议先维护好部门，再添加或调整员工，这样员工账号、数据范围和后续日报统计会更清楚。

### 1.2.3 角色管理

角色管理用于控制员工能看到哪些菜单、能使用哪些功能，以及能看到哪些范围的数据。部门管理员可以维护角色基本信息、调整角色权限、设置数据范围，也可以给角色添加或移除员工。

这个菜单比较关键，因为它会直接影响员工登录后的系统入口。尤其是“修改权限”和“更新数据范围”，操作前最好先确认角色用途，避免误把不该开放的功能开放出去，或者让员工看不到自己需要处理的数据。

## 1.3 系统设置

系统设置用于维护系统运行所需的基础数据和管理工具。部门管理员当前拥有菜单、参数、字典、文件、公告、消息等相关权限。

### 1.3.1 菜单管理

菜单管理用于维护系统功能入口。可以新增、编辑或删除菜单。  
这个功能一般不建议频繁调整，因为菜单会影响系统导航、角色授权和页面访问。如果只是业务管理员日常使用，通常更多是查看和少量维护。

### 1.3.2 参数配置

参数配置用于维护系统运行参数。项目里的工作项积分就用到了参数配置，例如“工作项允许补填天数”，默认是允许补填最近 2 天内的日报。

参数往往会影响业务规则，修改前要先确认参数含义。比如补填天数改大，会让员工可以补更多历史日报；改小，则可能导致员工无法补填之前遗漏的日报。

### 1.3.3 数据字典

数据字典用于维护系统中的基础选项，比如状态、类型、分类等。很多页面上的下拉选项都可能来自数据字典。

部门管理员可以维护字典本身，也可以维护字典数据，并控制启用或禁用。这里的重点是保持字典值稳定，不要随意删除已经被业务数据使用过的选项，否则历史数据展示时可能不容易理解。

### 1.3.4 文件管理

文件管理用于查看系统中的文件记录。当前部门管理员主要拥有查询能力，可以用来确认系统内上传或生成过的文件信息。

在工作项积分中，日报明细可以上传图片佐证，这些文件也会进入系统文件体系。文件管理更偏后台查询和追溯，不是日常高频操作入口。

### 1.3.5 公告管理

公告管理用于发布和维护系统公告。部门管理员可以查询、新建、编辑、删除公告，适合发布部门通知、系统提醒、制度说明等内容。

系统本身也把通知公告作为 OA 办公能力的一部分，公告不只是“发一条消息”，还可以配合查看记录、详情页等功能，帮助管理员确认通知内容是否被用户看到。

#### 1.3.5.1 公告详情

公告详情用于查看单条公告的具体内容。管理员在编辑或核对公告时，可以通过详情页确认标题、正文、附件或展示效果是否符合预期。

#### 1.3.5.2 我的通知

我的通知用于查看当前账号收到的通知公告。部门管理员既可以发布公告，也可能作为接收人查看别人发布给自己的通知。

#### 1.3.5.3 我的通知公告详情

我的通知公告详情用于查看收到的某条通知公告内容。这个页面更偏个人阅读场景，主要用于确认通知正文和相关信息。

### 1.3.6 消息管理

消息管理用于维护系统站内消息。部门管理员可以查询消息、发送消息和删除消息。

工作项日报审核也会和站内消息产生联动：审核通过或审核失败后，系统会给日报提交人发送消息提醒。管理员可以通过消息体系了解系统通知的发送情况。

## 1.4 网络安全

网络安全模块主要用于账号安全和审计追踪。系统支持登录限制、日志、操作记录等安全能力，部门管理员当前能使用其中一部分。

### 1.4.1 登录失败锁定

登录失败锁定用于查看或配置登录失败后的锁定策略。这个功能主要是为了防止账号被反复尝试登录。

如果有员工反馈账号被锁定，可以结合登录登出记录一起排查，看是输错密码导致，还是存在异常登录尝试。

### 1.4.2 登录登出记录

登录登出记录用于查询用户登录、退出系统的记录。  
当需要确认某个员工是否登录过系统、什么时候登录、是否存在异常登录行为时，可以从这里查。

### 1.4.3 用户操作记录

用户操作记录用于查询系统内的关键操作日志，并查看操作详情。  
比如数据被修改、公告被删除、权限发生变化时，可以通过操作记录追踪是谁在什么时候做了什么。这个菜单在问题排查和安全审计时很有用。

## 1.5 工作项积分

工作项积分是部门管理员当前最需要重点关注的模块。它的完整流程是：先维护可填报的工作项，再由员工填写日报，管理员审核日报，最后通过积分报表查看统计结果。

项目里这个模块有比较完整的设计：工作项有类型、描述、评分标准、标准分和启用状态；日报有草稿、待审核、审核通过、审核失败四种状态；日报明细支持完成说明和图片佐证；审核时可以调整最终分、填写扣分原因；审核结果会通过站内消息提醒提交人。

### 1.5.1 工作项维护

工作项维护是积分体系的基础。这里分成两层：左侧是“工作项类型”，右侧是具体“工作项”。

工作项类型可以理解为大类，比如日常、运维、核验、办公、学习等。具体工作项则是员工填日报时选择的内容，每个工作项可以设置名称、描述、评分标准、标准分、排序和启用状态。

使用时建议先把类型规划好，再添加具体工作项。比如不要把所有事情都放在一个“日常”类型里，否则后面统计时看不出工作结构。工作项名称尽量清楚，评分标准尽量写得可判断，比如说明什么情况下给标准分、什么情况下需要扣分。

工作项可以停用。对于已经被历史日报使用过的工作项，更建议停用而不是直接删除，这样既不会影响后续选择，也能保留历史数据的可读性。

### 1.5.2 我的日报

我的日报用于填写自己的每日工作内容。页面支持选择日报日期，系统会根据参数限制可补填范围，当前项目默认是最近 2 天内可以补填。

填写时，先从工作项类型中筛选，再把对应工作项添加到“已填明细”。每条明细需要写完成说明，也可以上传图片作为佐证。系统支持先保存草稿，确认无误后再提交审核。

这里有几个使用要点：  
日报不是简单写一句“完成工作”，而是要尽量选择准确的工作项，并写清楚完成内容。提交后日报会进入待审核状态，正常情况下不能继续编辑；如果审核失败，会显示失败原因，员工可以修改后再次提交。

### 1.5.3 日报审核

日报审核用于处理员工提交的日报。默认会关注待审核数据，也可以按员工、状态、日期范围查询。

管理员进入详情后，可以看到员工、部门、日期、状态，以及每条日报明细的工作项类型、工作项名称、完成说明、标准分和佐证图片。审核时可以根据实际完成情况调整最终分，也可以填写扣分原因。

审核通过后，该日报会进入审核通过状态，并计入积分报表。审核失败时需要填写失败原因，系统会记录审核历史，并通过站内消息提醒提交人。  
这个菜单的重点不是“点通过”，而是保证工作项选择合理、完成说明可信、最终分有依据。

### 1.5.4 积分报表

积分报表用于查看部门或员工的积分统计。页面支持按开始日期、结束日期、员工姓名、机构进行查询。

报表先按员工汇总展示，通过日报天数、明细数量和总分可以快速判断一段时间内的工作量情况。点击日期明细后，可以进一步查看某个员工每天的总分，再进入工作项详情，看到具体填写内容、标准分、最终分、扣分原因和佐证图。

这里建议管理员重点看三类情况：第一，积分明显偏高或偏低的员工；第二，日报天数少但总分高、或明细数量异常的情况；第三，经常被扣分或审核失败的工作项。这样报表不只是统计结果，也能反向帮助优化工作项设置和日报填写质量。

## 1.6 文档中心

文档中心用于维护帮助说明、处理反馈和查看更新记录。项目 README 里也强调了在线文档、意见反馈、版本记录这些能力，目的是让系统说明沉淀下来，减少重复沟通。

### 1.6.1 帮助文档

帮助文档用于维护系统操作说明和目录。部门管理员可以新增目录、修改目录，也可以查询、新建、更新或删除帮助文档。

建议把常见操作写成短文档，比如“如何填写日报”“日报审核标准”“公告发布注意事项”等。这样员工遇到问题时可以先查文档，不用每次都找管理员确认。

### 1.6.2 意见反馈

意见反馈用于查看或处理用户提交的反馈。  
如果员工在使用系统时遇到问题，或者对功能有优化建议，可以通过反馈沉淀下来，管理员后续可以集中查看和跟进。

### 1.6.3 更新日志

更新日志用于查看系统版本或功能更新记录。当前部门管理员主要拥有查询权限。

当系统功能发生变化，比如新增工作项积分、调整公告、修改安全策略时，可以通过更新日志了解变化内容，方便管理员同步给部门成员。

## 1.7 使用建议

日常使用可以按这个顺序来：先在首页看通知、待审核和积分概览；人员变动时维护组织架构；有制度或消息要同步时用公告和消息；工作项积分则按“维护工作项、填写日报、审核日报、查看报表”的流程持续使用。

需要特别谨慎的操作包括删除数据、修改角色权限、更新数据范围、禁用员工、重置密码、删除或停用工作项。这些操作可能影响多人使用或历史统计，执行前最好先确认清楚。
