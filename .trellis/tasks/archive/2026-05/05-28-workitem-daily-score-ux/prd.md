# 工作项与日报积分体验优化

## Goal

优化工作项维护、我的日报、积分报表三个工作项积分相关页面的操作体验，并补齐支撑这些体验所需的后端能力。

## Requirements

* 工作项维护页面支持批量选择并批量删除工作项。
* 我的日报页面的工作项类型默认不选中，允许取消选择；未选中类型时，可选工作项展示全部启用工作项。
* 我的日报页面增强三列视觉层次，右侧已填明细需要更突出。
* 我的日报页面顶部在日报日期选择右侧展示当前最新状态；审核通过时不再展示历史失败原因。
* 我的日报页面增加审批历史入口，展示提交、审核、再提交、再审核等时间节点。
* 我的日报页面在选择日报日期时即提示“只允许填报最近 X 天内的日报”，不能只等到保存时才提示。
* 积分报表的日期明细改为一个弹窗左右两栏展示，左侧为日期+总分，右侧为工作项详情；右侧表格单独展示类型列，并用标签标记工作项类型。
* 积分报表按员工姓名模糊搜索，不再要求输入员工 ID。
* 积分报表的机构筛选改为树形选择，不再使用手工输入部门 ID，且机构选项必须受工作项日报数据范围限制。
* 我的日报填报人可访问工作项类型和可选工作项只读接口，不需要额外授予工作项维护查询权限。
* 日报审核和积分报表必须按角色数据范围限制可见员工数据；仅个人可见时只能看到本人日报和积分。

## Acceptance Criteria

* [ ] 工作项维护表格可勾选多条工作项，点击批量删除后调用批量删除接口并刷新列表。
* [ ] 我的日报首次进入时工作项类型无选中态，可选工作项展示全部；点击已选类型可取消选择并恢复展示全部。
* [ ] 我的日报只在最新状态为审核失败时展示失败原因；审核通过后不残留旧失败原因。
* [ ] 我的日报审批历史弹窗可看到提交和审核记录，且按时间顺序形成时间线。
* [ ] 日报日期切换到允许补填范围外时，立即提示并禁用保存/提交。
* [ ] 积分报表点击日期明细后打开单个两列弹窗，切换日期时右侧工作项详情同步更新，且类型列以标签形式展示。
* [ ] 积分报表可按员工姓名搜索，查询结果受当前用户角色数据范围限制。
* [ ] 积分报表机构筛选为树形选择组件，普通用户仅能选择当前数据范围内机构。
* [ ] 普通填报人仅拥有我的日报权限时，进入我的日报不会因 `/workitem/type/query` 或 `/workitem/item/list` 报无权限。
* [ ] 日报审核列表、审核详情、审核提交均不能越过当前用户角色数据范围。

## Definition of Done

* 前端 lint 或构建检查通过，若受现有环境限制无法运行需说明。
* 后端 Java 编译或可用静态检查通过，若受现有环境限制无法运行需说明。
* 不覆盖用户已有未提交改动。

## Technical Approach

* 后端为工作项增加批量删除接口，复用单条删除校验逻辑并软删除。
* 后端在日报提交时写入一条历史记录，复用现有审核历史表的 `auditResult=WAIT_AUDIT` 表示提交节点；审核动作继续写入审核通过/失败节点。
* 后端在工作项类型/可选工作项只读接口上使用 Sa-Token OR 权限，允许工作项维护查询权限或我的日报权限访问。
* 后端为工作项日报新增数据范围类型，审核和积分报表查询由 Service 计算当前用户可见员工 ID 后传入 Mapper 过滤。
* 前端我的日报读取配置 `work_item_allow_replenish_days`，在日期变更、保存、提交入口统一做本地范围校验，并保留后端最终校验。
* 前端积分报表复用现有日期、工作项两个接口，在一个弹窗中联动展示。
* 前端积分报表将员工查询条件从员工 ID 改为员工姓名关键字。
* 前端积分报表复用部门树选择组件，并通过业务接口加载当前用户可见机构树。

## Out of Scope

* 不新增数据库表或迁移脚本。
